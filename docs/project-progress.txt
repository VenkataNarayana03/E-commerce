Important Database Rules
------------------------
users:
- email must be unique.
- role is restricted to:
  - customer
  - admin

categories:
- name must be unique.
- slug must be unique.

products:
- belongs to a category.
- slug must be unique.
- price cannot be negative.
- stock_quantity cannot be negative.

cart_items:
- belongs to a user.
- belongs to a product.
- quantity must be greater than 0.
- one user cannot have duplicate cart rows for the same product.

orders:
- belongs to a user.
- order_number must be unique.
- status is restricted to:
  - pending
  - confirmed
  - processing
  - shipped
  - out_for_delivery
  - delivered
  - cancelled
- payment_method is restricted to:
  - cod
  - upi
  - razorpay
- subtotal cannot be negative.
- shipping_fee cannot be negative.
- total_amount cannot be negative.

order_items:
- belongs to an order.
- optionally belongs to a product.
- unit_price cannot be negative.
- quantity must be greater than 0.
- line_total cannot be negative.

payments:
- belongs to one order.
- order_id is unique, meaning one order has one payment record.
- amount cannot be negative.
- method is restricted to:
  - cod
  - upi
  - razorpay
- status is restricted to:
  - pending
  - paid
  - failed
  - refunded
- transaction_id is unique when present.

Backend API Endpoints Added
---------------------------
POST /api/auth/register:
- Public endpoint.
- Creates a customer account.

- Public endpoint.

- Verifies password.

Request body:

- Protected endpoint.
- Requires Authorization: Bearer token.
- Returns current user profile.

- Protected customer endpoint.
- Requires valid JWT token.
- Returns customer dashboard access message and user data.

GET /api/admin/dashboard:
- Protected admin endpoint.
- Requires valid JWT token.
- Requires user role to be admin.
- Returns admin dashboard access message and user data.


JWT Details
-----------
JWT token contains:
- sub: user id
- exp: expiry datetime

JWT config comes from .env:
- JWT_SECRET_KEY
- JWT_ALGORITHM
- ACCESS_TOKEN_EXPIRE_MINUTES

Frontend stores the token using:
- localStorage key: accessToken

Frontend sends token using:
- Authorization: Bearer <token>


Password Hashing Details
------------------------
Passwords are never stored directly.

When registering:
- User password is converted to a bcrypt hash.
- Hash is saved in users.password_hash.

When logging in:
- Plain password from request is compared with saved bcrypt hash.
- Login succeeds only if they match.

Password length:
- RegisterRequest allows passwords from 8 to 72 characters.
- 72 characters is the bcrypt safe limit.


Admin Access Details
--------------------
There is no public admin registration endpoint.

cd backend
.\.venv\Scripts\python.exe -m app.utils.create_admin --email admin@example.com --password Password123 --name "Admin User"

- Admin user is redirected to /admin.
- /admin calls GET /api/admin/dashboard.
- Backend allows access only if user.role is admin.
