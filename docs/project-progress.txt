CORE CODE TECHNIQUES & ARCHITECTURE PATTERNS USED IN THE WEBSITE
================================================================================

1. FRONTEND CODE TECHNIQUES (React + Vite + Axios + Bootstrap)
--------------------------------------------------------------

A. Context API & Global State Management:
   - AuthContext (`src/context/AuthContext.jsx`):
     - Stores logged-in user state and JWT access token in `localStorage`.
     - Automatically restores session on app reload via `GET /api/auth/me`.
     - Provides login, register, and logout handlers across the application.
   - CartContext (`src/context/CartContext.jsx`):
     - Dual-mode operation: Syncs with backend REST endpoints (`cartService.js`) when logged in; falls back to guest cart state when unauthenticated.
     - Enforces role rules (prompts guest users to login for order placement).
     - Manages `addToCart`, `updateQuantity`, `increaseQuantity`, `decreaseQuantity`, `removeFromCart`, `clearCart`, and live `subtotal` / `totalItems` state.

B. Axios Interceptor Pattern (`src/services/api.js`):
   - Centralized Axios instance configured with `baseURL` (`import.meta.env.VITE_API_URL`).
   - Request Interceptor: Automatically inspects `localStorage.getItem("accessToken")` and attaches `Authorization: Bearer <token>` to every outgoing HTTP request.

C. Route Protection & Authorization (`src/routes/ProtectedRoute.jsx`):
   - Higher-Order Wrapper Component checking `useAuth()`.
   - Redirects unauthenticated users to `/login?redirect=...`.
   - Supports `adminOnly` flag to restrict admin routes (`/admin`) exclusively to users with `user.role === 'admin'`.

D. Controlled Form State & Generic Input Handler:
   - Uses generic input handler for form state across Login, Register, Checkout, Admin forms:
     `const handleChange = (e) => { const { name, value, type, checked } = e.target; setFormData(prev => ({ ...prev, [name]: type === 'checkbox' ? checked : value })); }`
   - Keeps code DRY and handles text, number, select, and checkbox controls cleanly.

E. Dual Currency Formatting Utility (`src/utils/price.js`):
   - `formatDualPrice(amount)` formats prices into standard USD ($) alongside converted INR (₹) estimates, providing consistent currency presentation across Product Grid, Details, Cart, Checkout, and Order History.

F. Non-blocking Toast Feedback (`react-toastify`):
   - Global `ToastContainer` rendered in `App.jsx`.
   - Action notifications (`toast.success()`, `toast.error()`, `toast.info()`) trigger instantly for Add to Cart, Item Removal, Status Updates, Product/Category CRUD, and Checkout confirmation.

G. Modern Responsive Layout (Bootstrap 5):
   - Card grids (`col-sm-6 col-lg-4`), rounded containers (`rounded-4`), sticky sidebars (`sticky-top`), rounded badges (`rounded-pill`), and overlay modals (`modal show d-block`).


2. BACKEND CODE TECHNIQUES (FastAPI + SQLAlchemy + Pydantic)
-----------------------------------------------------------

A. Layered Clean Architecture (Routes -> Services -> Models & Schemas):
   - Routes (`app/routes/`): Responsible only for HTTP endpoint definition, dependency injection, status code mapping, and response model declarations.
   - Services (`app/services/`): Contains core business logic (stock verification, order total calculation, password hashing, cart operations).
   - Models (`app/models/`): SQLAlchemy 2.0 mapped classes with typed columns (`Mapped[T]`), foreign keys, check constraints, and relationships (`relationship(cascade="all, delete-orphan")`).
   - Schemas (`app/schemas/`): Pydantic v2 data validation schemas (`Field(ge=0, min_length=...)`) with `from_attributes = True` for ORM conversion.

B. FastAPI Dependency Injection (`app/dependencies/auth.py` & `app/database.py`):
   - `get_db`: Yields database session scope with automatic cleanup (`finally: db.close()`).
   - `get_current_user`: Extracts Bearer token from header, decodes JWT with `JWT_SECRET_KEY`, validates user existence, and verifies `is_active` and `is_blocked` status.
   - `get_current_admin`: Extends `get_current_user` to verify `current_user.role == 'admin'`, returning `403 Forbidden` for non-admin users.

C. Preventing N+1 Database Queries (`joinedload`):
   - Uses SQLAlchemy `joinedload` option on queries to eager-load associated entities in a single SQL query:
     `select(Order).options(joinedload(Order.items), joinedload(Order.user))`
     `select(CartItem).options(joinedload(CartItem.product).joinedload(Product.category))`

D. Atomic Transactions & Stock Control (`app/services/order_service.py`):
   - Order creation executes inside a single database transaction (`db.commit()`):
     1. Validates stock availability for every cart product (`product.stock_quantity >= item.quantity`).
     2. Generates unique order number (`ORD-YYYYMMDDHHMMSS-XXXXXX`).
     3. Creates `Order` and `OrderItem` records.
     4. Atomically deducts purchased stock (`product.stock_quantity -= item.quantity`).
     5. Clears user cart items (`db.delete(cart_item)`).
     6. Commits transaction or rolls back on failure.

E. Idempotent Data Seeding Scripts (`app/utils/seed_products.py`, `seed_categories.py`):
   - Repeat-safe seeding logic: Queries records by `slug`. If record exists, updates attributes; if not, inserts new row. Enables running seed scripts repeatedly without duplicate key crashes.

F. Secure Password Hashing & JWT Authentication (`app/services/security.py`):
   - Passwords hashed using `bcrypt` salted hashing algorithm.
   - JWT access tokens created with payload (`sub`, `exp`), signed using SHA-256 HMAC algorithm.


3. ADMIN PAGE TO USER PAGE LIVE DATA UPDATING & SYNCHRONIZATION
--------------------------------------------------------------

A. Product Catalog & Stock Synchronization (Admin -> Customer / Guest):
   - When an Admin creates, updates, or deletes a product in Admin Dashboard (`Admin.jsx` -> `POST /api/products` or `PUT /api/products/{id}` or `DELETE /api/products/{id}`):
     1. Database State: SQLAlchemy updates the `products` table in Neon PostgreSQL.
     2. User Pages Effect: When any Guest or Customer visits the Home Page (`/`), Product Catalog (`/products`), or Product Details (`/products/:id`), React components execute `useEffect` hook to fetch live product data via `api.get("/products")`.
     3. Out-of-Stock Handling: If an admin reduces a product's `stock_quantity` to 0 or sets `is_active = false`, the customer's "Add to Cart" button automatically disables (`disabled={product.stock_quantity === 0}`).

B. Category Management Updates (Admin -> Customer / Guest):
   - When an Admin creates, edits, or deactivates a category (`Admin.jsx` -> `POST /api/categories` or `PUT /api/categories/{id}`):
     1. Database State: Updates `categories` table in PostgreSQL.
     2. User Pages Effect: Category filter dropdowns on the `/products` page dynamically fetch live categories via `GET /api/categories`. Deactivated categories (`is_active = false`) are automatically filtered out.

C. Order Status Live Tracking Synchronization (Admin -> Customer):
   - When an Admin changes an order status from the Admin Orders Management table (`Admin.jsx` -> `PUT /api/admin/orders/{order_id}/status`, e.g., `Pending` -> `Confirmed` -> `Processing` -> `Shipped` -> `Out For Delivery` -> `Delivered` -> `Cancelled`):
     1. Database State: The `orders.status` column is updated in PostgreSQL.
     2. Customer My Orders Page Effect: When the customer visits or refreshes **My Orders** (`/orders`), the component calls `GET /api/orders`. The order status badge immediately updates to reflect the live status (e.g. `SHIPPED`, `DELIVERED`).

D. Order Placement Stock Deduction & Admin Revenue Analytics (Customer -> Admin):
   - When a Customer places an order during Checkout (`Checkout.jsx` -> `POST /api/orders`):
     1. Backend Execution: `order_service.create_order` automatically reduces product inventory (`Product.stock_quantity -= qty`).
     2. Admin Page Effect: The new order immediately appears in the Admin Orders Management table (`GET /api/admin/orders`), and Total Revenue and Total Orders metric cards update via `GET /api/admin/summary`.
